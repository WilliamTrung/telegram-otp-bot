# Project Context: Zero-Cost Telegram Chatbot Gateway

## 📌 Overview
This project is a lightweight, ultra-low-footprint Telegram chatbot designed to operate as an SMS/Text gateway. The defining operational constraint is **Absolute Zero Cost ($0/month)** for infrastructure, routing, and maintenance.

---

## 🛠️ Tech Stack & Infrastructure

| Component | Technology | Selection Rationale |
| :--- | :--- | :--- |
| **Language** | Go (Golang) 1.23+ | Native binaries, minimal memory overhead (<20MB RAM), fast execution. |
| **API Library** | `go-telegram-bot-api/v5` | Mature, idiomatic, community-tested wrapper for the Telegram Bot API. |
| **Containerization** | Docker / Docker Compose | Platform-agnostic, easily portable, reproducible environments. |
| **Base Image** | Multi-stage Alpine Linux | Keeps the final production container footprint down to ~15MB. |

---

## 📐 Architecture & Cost-Saving Strategy

### 1. Long Polling vs. Webhooks
* **Chosen Approach:** **Long Polling (`GetUpdatesChan`)**
* **Why:** Webhooks require a publicly accessible HTTPS endpoint, which demands a domain name, SSL/TLS certificate management, and an open inbound port (or a reverse proxy like Traefik/Nginx). 
* **The $0 Edge:** Long polling utilizes outbound HTTPS requests to Telegram's servers. This completely bypasses the need for public IPs, port forwarding, or paid cloud ingress. The bot can run securely behind a strict home NAT, a Raspberry Pi, or a free-tier cloud instance (e.g., Oracle Cloud Free Tier).

### 2. State & Data Handling
* **Stateless by Default:** To maintain zero cost and zero storage overhead, the bot processes messages ephemerally. 
* **Scaling Limit:** Because it relies on a single long polling loop, this architecture is optimized for vertical scaling on a single single-core instance.

---

## 🔒 Security & Environment Configuration

* **Secrets Management:** The Telegram HTTP API Bot Token must never be hardcoded. It is injected at runtime via Docker environment variables using a `.env` file.
* **Network Isolation:** The container requires outbound internet access to `api.telegram.org` but requires **zero inbound open ports** exposed to the public internet.
* **Process Security:** The Go binary is compiled statically, stripping debugging symbols to minimize vulnerability attack surfaces within the container.

## 📋 Operational Runbook

### Required Environment Variables
* `TELEGRAM_BOT_TOKEN`: The unique authorization token generated by `@BotFather`.

### Deployment Checklist
1. Provision a `.env` file containing the active bot token.
2. Spin up the container stack via `docker compose up -d`.
3. Monitor system logs via `docker compose logs -f` to ensure successful HTTP 200 handshakes with Telegram's polling gateway.
4. Set the `restart: unless-stopped` policy to ensure automatic recovery if the host machine reboots.
