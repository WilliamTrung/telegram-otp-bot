Integration Guide

Follow these details to integrate the verification gateway into your own service backend.

POST
/api/verify/init

Initialize a new verification session. Returns a unique token and the Telegram redirection deep link.

Headers

Authorization: Bearer <YOUR_API_KEY>
Content-Type: application/json

Request Body

{
  "callback_url": "https://your-service.com/api/webhook",
  "user_reference": "user_id_101"
}

Response Payload

{
  "token": "auth_90a36bc8de...",
  "telegram_link": "https://t.me/your_bot_username?start=auth_90a36bc8de...",
  "expires_at": "2026-06-05T13:40:00Z"
}
WEBHOOK
POST [callback_url]

When the user hits "START" in their Telegram app, the gateway processes the update and triggers a POST callback notification containing user details to the URL specified during initialization.

Webhook Payload

{
  "event": "verification.completed",
  "token": "auth_90a36bc8de...",
  "user_reference": "user_id_101",
  "status": "VERIFIED",
  "telegram": {
    "chat_id": 98765432,
    "username": "telegram_user",
    "first_name": "John"
  },
  "timestamp": "2026-06-05T13:35:10Z"
}

Expected Response

Your webhook handler **MUST** return a 200 OK status code. Any other status code or timeout will trigger the exponential backoff retry worker. If failures persist consecutively 5 times, the gateway's Circuit Breaker trips open for 15 seconds to prevent request flooding.
